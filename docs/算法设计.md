# 加密视频防篡改算法设计（VideoGuard）

> 目标：视频经本算法加密后，任何"删除 / 剪辑 / 拼接 / 重编码 / PS / AI 修改画面 / 整体掉包"都能被检测出来，并尽可能定位到具体的字节区间或时间点。

---

## 1. 设计目标

| 编号 | 目标 |
|---|---|
| G1 | 加密后的视频具备机密性：无口令者无法获取画面内容 |
| G2 | 任何字节级改动（删除、截断、拼接、改元数据）可被检测并定位到块区间 |
| G3 | 任何画面级改动（PS 修图、AI 换脸/修复、裁剪、遮挡）可被检测并定位到秒 |
| G4 | 重编码/转码行为可被识别（即使画面内容未变） |
| G5 | 整体掉包、伪造重签可被识别 |
| G6 | 合法接收方可正常解密播放；验证可离线进行 |

## 2. 威胁模型

攻击者的能力按等级划分：

| 等级 | 能力 | 对应攻击 |
|---|---|---|
| A0 | 只有密文文件 | 破坏密文字节、删除、截断、拼接密文 |
| A1 | 可完整解密（掌握口令） | 解密后剪辑、重编码、重新打包 |
| A2 | 获得明文副本（录屏/泄漏/分发给他人后被导出） | 对明文进行剪辑、PS、AI 修改后重新发布 |
| A3 | 上述全部 + 伪造文件替换 | 掉包、伪造签名 |

**核心假设**：攻击者不掌握签名私钥（私钥由发布方持有，永不随视频分发）。

攻击分类：

- **T1 字节级篡改**：删除片段、截断、拼接、翻转字节、修改元数据。
- **T2 重编码攻击**：转码、压缩、调色、加滤镜、加水印。
- **T3 内容级篡改**：裁剪画面、贴图遮挡、PS 修改、AI 换脸/局部重绘/AI 修复。
- **T4 整体替换**：用另一段视频冒充原件。

## 3. 总体架构：三层哈希 + 一层加密

```
┌──────────────────────────────────────────────────────────────┐
│ L0 机密层    AES-256-GCM 加密（随机内容密钥 CK，口令派生 KEK 封装） │
├──────────────────────────────────────────────────────────────┤
│ L1 文件级    1 MiB 分块 SHA-256 + Merkle 树 + Ed25519 数字签名   │  → 检测 T1，定位到字节区间
├──────────────────────────────────────────────────────────────┤
│ L2 结构级    时长 / 帧率 / 分辨率 / 总帧数 / 采样序列指纹          │  → 检测删除、插入、裁剪导致的时长结构变化
├──────────────────────────────────────────────────────────────┤
│ L3 画面级    逐秒采样帧的感知哈希（pHash + dHash）序列，签名绑定   │  → 检测 T2/T3，定位到秒
├──────────────────────────────────────────────────────────────┤
│ L4 音频级    16 kHz PCM 每秒分片 SHA-256                       │  → 检测音频删除、替换、篡改
├──────────────────────────────────────────────────────────────┤
│ L5 水印层（扩展）脆弱水印 + 鲁棒水印                             │  → 重编码判定与来源追溯
└──────────────────────────────────────────────────────────────┘
```

### 设计原则

1. **完整性绑定"像素内容"而非仅文件字节**：L1 检测字节变化，L3 检测画面变化。攻击者重编码（字节全变）后，L1 报"字节变化"，L3 仍能判定"画面是否被改"。
2. **分层判定、独立定位**：字节级定位到 1 MiB 块区间，画面级定位到秒。
3. **非对称签名**：即使攻击者拥有口令（A1，可解密观看），也无法重新生成合法签名，改后重加密必被识破。
4. **清单与公钥可公开分发**：任何人拿到任一版本的视频文件，都可以离线验证它是否被改动过。

## 4. 密钥体系

| 密钥 | 生成 | 用途 |
|---|---|---|
| CK（内容密钥） | 每个文件随机 256 bit | AES-256-GCM 加密文件本体 |
| KEK | `PBKDF2-HMAC-SHA256(口令, 盐, 600000 次)` 派生 256 bit | 封装/解封 CK（生产环境建议 Argon2id） |
| 签名私钥 | Ed25519，发布方生成一次 | 对清单摘要签名 |
| 签名公钥 | 随清单公开分发 | 验证签名 |

- **密钥封装**：`wrapped = AES-256-GCM(KEK, 0⁹⁶).encrypt(CK)`。KEK 因盐随机而每个文件唯一，故固定 nonce 安全。
- **口令更新**：更换口令只需重新封装 CK，视频本体无需重加密（重封装成本 O(1)）。
- **降级模式**：无公钥设施时可用 HMAC-SHA256（密钥由口令 + 独立盐派生），但该模式仅保证完整性、不具不可抵赖性，清单中会显式标记。

## 5. 容器格式（`.vgd`）

```
偏移 0       : MAGIC = "VGD1"                       (4 字节)
偏移 4       : header_len                          (4 字节，大端)
偏移 8       : header JSON                          (加密元数据)
随后        : ciphertext                            (payload 的 AES-256-GCM 密文)
文件末尾     : GCM tag                              (16 字节)
```

header 字段：

```json
{
  "format": "videoguard/1",
  "cipher": "aes-256-gcm",
  "kdf": "pbkdf2-hmac-sha256",
  "kdf_iters": 600000,
  "salt": "<base64>",
  "wrapped_key": "<base64>",
  "nonce": "<base64>",
  "manifest_len": 12345,
  "payload_len": 23456789
}
```

payload = `manifest_json（含签名） || 原始视频文件字节`，整体以 4 MiB 块流式 GCM 加密。

**第一道防线**：密文任何一个字节被改动，GCM 标签校验立即失败——攻击者甚至无需进入哈希比对环节即被识破。

## 6. 清单（manifest）与签名

```json
{
  "format": "videoguard-manifest/1",
  "file": {
    "name": "sample.mp4", "size": 1234567, "sha256": "...",
    "duration": 10.0, "width": 640, "height": 360,
    "fps": 25.0, "frame_count": 250, "has_audio": true
  },
  "blocks": {
    "size": 1048576, "count": 2,
    "leaves": ["<sha256>", "<sha256>"],
    "merkle_root": "<sha256>"
  },
  "frames": {
    "sample_interval_sec": 1.0, "count": 10,
    "samples": [{"i": 0, "t": 0.0, "phash": "<16hex>", "dhash": "<16hex>"}, "..."]
  },
  "audio": {
    "sample_rate": 16000, "chunk_sec": 1.0, "count": 10,
    "chunks": ["<sha256>", "..."]
  },
  "created_at": "2026-11-06T03:00:00+00:00",
  "sign_salt": "<base64>",
  "signer": "ed25519:<base64 公钥>",
  "signature": "<base64>"
}
```

**签名流程**：

1. 将清单（不含 `signature` 字段）规范序列化：`canonical = json.dumps(obj, sort_keys=True, separators=(",", ":"))`；
2. `digest = SHA-256(canonical)`；
3. `signature = Ed25519_Sign(私钥, digest)`（降级模式为 `HMAC-SHA256(派生密钥, digest)`）。

**验证流程**：重算 canonical → digest → 公钥验签。签名失败即判定"掉包 / 伪造"，且该判定先于一切内容比对。

## 7. 核心算法细节

### 7.1 分块哈希与 Merkle 树（L1）

- 块大小 `B = 1 MiB`；每块 `leaf = SHA-256(chunk)`；
- Merkle 树：奇数层复制末叶补偶，逐层两两拼接哈希，根即 `merkle_root`；
- **定位**：验证时逐块重算，输出不匹配块的连续区间 → 报告"第 X–Y 块（约 Z MiB 处）被修改"；
- **安全**：SHA-256 碰撞/第二原像计算不可行，任何字节变化必然传导至根哈希与签名。

### 7.2 采样帧与感知哈希（L3）

**采样策略**：每 1 秒采样 1 帧（间隔可配置），采样时刻与时间戳对齐。删除/插入片段会破坏采样序列长度与对齐关系，与 L2 结构指纹协同检出。

**pHash（感知哈希，64 bit）**：

```
帧 → 灰度 → 缩放 32×32 → 2D DCT-II → 取左上 8×8 低频系数
   → 与中位数比较 → 64 bit
```

- 低频 DCT 系数对压缩噪声鲁棒（重编码后基本不变）；
- 对画面内容敏感（PS/AI 修改区域必然改变低频能量分布）。

**dHash（梯度哈希，64 bit）**：

```
帧 → 灰度 → 缩放 9×8 → 横向梯度差分 → 64 bit
```

- 对局部几何/边缘变化敏感，与 pHash 互补（例如小区域遮挡在 pHash 上可能不明显，但在 dHash 上会改变边缘结构）。

**距离与判定**：汉明距离 `h = popcount(a xor b)`。

| 汉明距离 | 判定 |
|---|---|
| h ≤ 10 | 内容一致（容忍轻微压缩噪声） |
| 10 < h ≤ 20 | 疑似轻处理（调色/轻压缩）→ 结合水印与字节层判定 |
| h > 20 | **画面被修改**，报告具体秒 |

阈值可配置（PoC 默认 20 / 10）；`--strict` 场景可收紧。

**实测边界与对策**（PoC 实测发现，见 §11）：

- 模糊（boxblur）几乎不改变低频 DCT 系数 → 仅靠 pHash 会漏检（实测距离 ≤2 bit）。对策：dHash 在更细网格（16×16 分区梯度哈希）上重算 + 分块感知哈希（把帧切成 4×4 子块各自算 pHash，局部改动必然击中某子块）；
- 色相旋转 180° 不改变亮度低频结构 → pHash 距离仅 10 bit（被判"轻处理"）；反色/亮度剧烈变化 → 距离 > 20 bit 直接判篡改。轻微调色属设计允许的宽容带，需要零容忍时收紧阈值并启用脆弱水印。

### 7.3 结构指纹（L2）

清单记录时长、帧率、分辨率、总帧数。验证时比对（时长容差 ±0.3 s，帧数容差 ±3，分辨率必须精确一致）：

- 裁剪画面 → 分辨率不符 → 立即判定；
- 删除片段 → 时长/帧数不符 + 采样帧数不符 → 判定并定位；
- 插入片段 → 采样序列错位 + 对应秒的感知哈希大面积失配 → 判定。

### 7.4 音频完整性（L4）

音频解码为 16 kHz 单声道 s16le PCM，按 1 s 分片逐片 SHA-256。音频删除、替换、局部篡改均可检出。

### 7.5 水印层（L5，扩展设计）

PoC 未实现，属生产增强项：

- **脆弱水印**：每个 GOP 在 DCT 系数/运动矢量中嵌入指纹，任何重编码都会破坏它 → 用于判定"是否经过重编码"；
- **鲁棒水印**：扩频/变换域嵌入，抵御压缩与裁剪 → 用于"被删改后仍可追溯来源"。

分层定位：**哈希负责"检测 + 定位"，水印负责"重编码判定 + 溯源"**。

## 8. 算法流程（伪代码）

### protect（加密保护）

```
输入: 视频 V, 口令 P, 签名私钥 SK
1. salt ← random(16); CK ← random(32)
2. 探测 V → 时长/分辨率/fps/帧数
3. 抽取采样帧 → 逐帧计算 pHash/dHash
4. 解码音频 → 每秒分片哈希
5. 分块 SHA-256 → Merkle 根
6. 构建 manifest → canonical → digest → Ed25519 签名
7. KEK ← PBKDF2(P, salt); wrapped ← GCM(KEK).encrypt(CK)
8. 写容器: MAGIC + header + GCM(CK).encrypt(manifest ‖ V) + tag
```

### verify（容器验证）

```
1. 解析 header → 解封 CK（口令错误 → 失败）
2. GCM 解密 payload（标签不符 → "密文被篡改"）
3. 验签（失败 → "掉包/伪造"）
4. 逐块重算哈希 → 输出不匹配块区间
5. 结构比对（时长/分辨率/fps/帧数）
6. 逐采样帧重算感知哈希 → 输出画面被改的秒
7. 音频分片比对
8. 汇总判定 → 报告
```

### verify-plain（明文副本离线验证）

对任意一个"声称是原版"的视频文件，用**公开清单 + 公钥**执行第 3–7 步。这是抵御 A2 攻击（明文被改后重新分发）的关键手段：清单随视频公开，任何人可验证任何副本。

## 9. 检测能力矩阵

| 攻击 | L0 加密 | L1 块哈希 | L2 结构 | L3 感知哈希 | L4 音频 | 签名 | 结果 |
|---|---|---|---|---|---|---|---|
| 删除片段（字节级） | ✓ | ✓ 定位块区间 | ✓ 时长/帧数变 | ✓ 采样断裂 | ✓ | — | 检出+定位 |
| 截断/破坏密文 | ✓ GCM 失败 | ✓ | — | — | — | — | 检出 |
| 拼接/插入片段 | — | ✓ | ✓ | ✓ 采样错位 | ✓ | — | 检出+定位 |
| 修改元数据 | — | ✓ | — | — | — | — | 检出 |
| 重编码/转码 | — | ✓ 字节全变 | ≈ | h≤10 内容一致 | 轻微 | — | 识别为"重编码" |
| 调色/滤镜 | — | ✓ | ≈ | h>阈值 | — | — | 检出（严格模式） |
| PS 贴图/遮挡 | — | ✓ | ≈ | ✓ 定位到秒 | — | — | 检出+定位 |
| AI 换脸/局部重绘 | — | ✓ | ≈ | ✓ 定位到秒 | — | — | 检出+定位 |
| 裁剪画面 | — | ✓ | ✓ 分辨率变 | ✓ | — | — | 检出 |
| 音轨删除/替换 | — | ✓ | — | — | ✓ | — | 检出 |
| 整体掉包 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ 验签失败 | 检出 |
| 解密后改再重加密（无私钥） | — | ✓ | ✓ | ✓ | ✓ | ✓ 验签失败 | 检出 |

## 10. 安全性分析

- **机密性**：AES-256-GCM 语义安全；强度取决于口令熵（PBKDF2 600k 次迭代拖慢离线爆破；生产建议 Argon2id + 硬件密钥）。
- **完整性**：SHA-256 抗碰撞；Ed25519 抗伪造。攻击者无法在不知道私钥的情况下重签。
- **关键对抗性场景**：
  - A1（有口令、无私钥）：可解密观看，改后重加密 → 签名验证失败。
  - A2（有明文副本）：编辑后重新发布 → 与公开清单比对，块哈希/感知哈希双双失配，且定位到秒。
  - A3（掉包）：不同文件 → 块哈希与签名失败。
  - AI 全帧重绘（保持语义）：pHash 绑定像素低频系数，任何重绘都改变系数 → 检出。针对感知哈希的对抗性攻击（adversarial attack）是研究前沿，缓解手段为脆弱水印 + 鲁棒水印 + 原文件哈希三重绑定。
- **局限**：本算法保护的是"该文件/该内容实例"的完整性，无法识别"逐镜头重新拍摄"的语义模仿；轻微调色在宽容模式下可能低于阈值（设计上允许，严格模式可收紧）。

### 命令速览

```powershell
# 生成签名密钥对
python src\videoguard.py genkey --dir demo\out

# 加密保护（生成 .vgd 容器）
python src\videoguard.py protect demo\out\sample.mp4 demo\out\sample.vgd --privkey demo\out\identity.key

# 验证容器
python src\videoguard.py verify demo\out\sample.vgd --pubkey demo\out\identity.pub

# 导出公开清单（用于离线验证任何明文副本）
python src\videoguard.py manifest-export demo\out\sample.vgd --out demo\out\manifest.json

# 验证一个可疑副本
python src\videoguard.py verify-plain demo\out\ps.mp4 --manifest demo\out\manifest.json
```

口令通过环境变量 `VG_PASS` 或 `--passphrase` 提供。
