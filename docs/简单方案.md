# 极简防篡改方案（SimpleGuard）—— 非对称签名

> 需求：算法要**非常简单**，采用**非对称加密**方案；无论视频被加水印、改色彩、遮挡、插入、拼接、替换音轨，**只要视频文件出现一点改动，都必须被完全验证出来**。

## 1. 算法（一共三步）

```
①  H = SHA-256(视频文件全部字节)          —— 对整个文件求一次哈希
②  S = 私钥签名(H)                        —— 用非对称私钥对哈希签名
③  验证: 重算 H'，H' == H 且 公钥验签(S) 通过 → 未改动；否则 → 检出改动
```

一句话：**"给整个视频文件算一个指纹，再用私钥给指纹盖章，验证时重算指纹、公钥验章。"**

没有水印层、没有帧采样、没有感知哈希、没有分块——就一个哈希加一个签名。

## 2. 为什么"任何一点改动"都必然被发现

| 性质 | 保证 |
|---|---|
| SHA-256 是确定性哈希 | 输入变一个字节，输出哈希完全不同（雪崩效应） |
| SHA-256 抗碰撞 | 实际中不存在两个内容不同的文件算出相同哈希 |
| Ed25519 非对称签名 | 没有私钥的人，无法为改动后的新哈希伪造合法签名 |

因此所有攻击最终都表现为"文件字节变化"：

| 攻击 | 为什么必被检出 |
|---|---|
| 加水印 | 画面被改 → 文件字节变 → 哈希不同 |
| 改色彩（调色/反色） | 字节变 → 哈希不同 |
| 遮挡（贴图/打码） | 字节变 → 哈希不同 |
| 插入片段 | 字节变、文件变长 → 哈希不同 |
| 拼接/剪辑 | 字节变 → 哈希不同 |
| 替换音轨 | 字节变 → 哈希不同 |
| 重编码（哪怕画面看起来一样） | 字节变 → 哈希不同（本方案按"改动"报警） |
| 整体掉包 | 哈希不同；就算换成同哈希的不同文件，签名也验不过 |
| 只改 1 个字节 | 哈希不同 |
| 改视频后同步改哈希（无签名私钥） | 哈希对上了，但签名验不过 → 伪造被识破 |

## 3. "非对称加密"在这里的位置（重要说明）

- 对整段视频直接做非对称加密在工程上不可行：RSA/Ed25519 每次只能处理几十到几百字节，视频动辄几十 MB。
- 数字签名就是非对称密码学的标准用法：**私钥签名、公钥验证**。本方案的核心正是这个。
- 如果还需要"别人打不开视频"（保密性），标准做法是在签名之外**可选地**加一层对称加密（随机密钥 + AES-GCM，密钥用接收方公钥封装，即混合加密）。PoC 未做加密，因为本需求是"验证改动"，签名已完全满足；加密与否不影响验证能力。

## 4. 容器格式（.sgd）

```
偏移 0    : MAGIC = "SGD1"                    (4 字节)
偏移 4    : header_len                        (4 字节，大端)
偏移 8    : header JSON                        (签名信息)
随后     : 视频文件原始字节（一字未动，可直接取出播放）
```

header JSON：

```json
{
  "format": "simple-guard/1",
  "algorithm": "ed25519",
  "sha256": "<对视频部分计算的 SHA-256>",
  "signature": "<Ed25519 私钥对哈希的签名, base64>",
  "pubkey": "<公钥原始 32 字节, base64>",
  "size": 963017,
  "created_at": "2026-11-07T12:00:00+00:00"
}
```

## 5. 使用

```powershell
# 1) 生成密钥对（私钥离线保管，公钥可公开）
python src\simple_guard.py genkey --dir demo\out_simple

# 2) 签名打包 → sample.sgd（视频字节原样在容器里）
python src\simple_guard.py sign demo\out_simple\sample.mp4 demo\out_simple\sample.sgd --privkey demo\out_simple\identity.key

# 3) 验证容器（任何一点改动立即报警）
python src\simple_guard.py verify demo\out_simple\sample.sgd --pubkey demo\out_simple\identity.pub

# 4) 验证任意一个"声称是原版"的副本（防：拿到视频改完再发出去）
python src\simple_guard.py check demo\out_simple\watermark.mp4 --sigfile demo\out_simple\sample.sgd --pubkey demo\out_simple\identity.pub

# 5) 取出原始视频播放
python src\simple_guard.py extract demo\out_simple\sample.sgd --out demo\out_simple\extracted.mp4
```

退出码：`0` 完全一致；`1` 检出改动/伪造。

## 6. 实测（demo/out_simple/report.md）

10 类攻击（含"只改 1 字节"和"改视频后同步改哈希的聪明攻击"）全部被检出，无一漏报。

## 7. 与分层方案的对比

| | 极简方案（本方案） | 分层方案（docs/算法设计.md） |
|---|---|---|
| 复杂度 | 3 步：哈希 + 签名 + 验签 | 4 层检测 + 感知哈希 + 分块 Merkle |
| 检测能力 | 任何字节级改动 100% 检出 | 同样检出，且能区分"重编码但画面没变"、定位到秒 |
| 重编码怎么看 | 一律报警（更严格） | 识别为"字节变但画面一致" |
| 适用 | 要"完全验证、零改动容忍"的场景 | 要"区分重编码与画面篡改、定位篡改位置"的场景 |

**结论**：如果验收标准是"只要文件有任何一点改动就必须报出来"——选极简方案，它更简单、更严格、更容易讲清楚，也更容易审计。
